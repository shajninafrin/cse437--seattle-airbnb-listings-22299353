# CSE437 Final Project: Seattle Airbnb Price Prediction

## Executive Summary
This project predicts Seattle Airbnb nightly prices and examines which available listing
characteristics are associated with price. The target is `log_price`, calculated as `log1p`
of the cleaned, 1st-to-99th-percentile capped price. Two model families are compared: tuned
Ridge regression and tuned Random Forest regression.

The tuned Random Forest performs best on the held-out test set. It achieves dollar RMSE of
`$58.71`, dollar MAE of `$35.48`, and log-space $R^2$ of `0.525`. The median-price baseline has
dollar RMSE of `$84.06`, so the Random Forest reduces RMSE by `30.2%`.

**Target variable:** `log_price` (log-transformed nightly price, `log1p` of the outlier-capped
raw price).

## Dataset and Important Schema Finding
The source is the Seattle Airbnb Listings dataset from Kaggle:
https://www.kaggle.com/datasets/shanelev/seattle-airbnb-listings

The supplied file is `data/raw/seattle_01.csv`. It contains 7,576 rows and an 18-column legacy
schema, including `room_type`, `reviews`, `overall_satisfaction`, `accommodates`, `bedrooms`,
`bathrooms`, `price`, `latitude`, `longitude`, `address`, and `name`. It does not contain the
richer fields sometimes found in Inside Airbnb exports, such as amenities, availability,
host attributes, or detailed neighbourhood labels. The analysis therefore reports only results
supported by the supplied file.

The raw data contains 1,473 missing `overall_satisfaction` values. Missing satisfaction is
handled with a median imputation plus a `has_satisfaction` indicator. The CSV index is removed,
listing duplicates are audited, invalid or non-positive prices are removed, and prices are
capped at the 1st and 99th percentiles before the log transformation.

## Research Questions
1. Which available features most strongly affect Airbnb price in Seattle?
2. Can listing price be predicted accurately using the available property and review features?
3. Which listings are predicted poorly, and why?

## Feature Engineering and Selection
The final candidate set uses features available in the supplied schema: review count,
overall satisfaction, indicators for reviews and observed satisfaction, accommodates,
bedrooms, bathrooms, latitude, longitude, name length, address length, and room type.
Numeric features are screened with variance, weak-correlation, and collinearity checks;
categorical variables are one-hot encoded inside the modeling pipeline. PCA is used as an
exploratory dimensionality-reduction diagnostic, but the final models retain the interpretable
features rather than replacing them with opaque components.

Because amenities, availability, host attributes, and detailed neighbourhood fields are absent,
their effects cannot be estimated from this file. This is a limitation of the supplied data,
not evidence that those factors do not affect Airbnb prices.

## Modeling and Validation
The data is split once into a 15% held-out test set and an 85% training set. The training set
is used for five-fold cross-validation during tuning; the test set is used only for final
evaluation. The models are trained on log price and evaluated both in log space and after
converting predictions back to dollars.

Ridge uses a grid of 20 logarithmically spaced alpha values from `1e-3` to `1e3` and obtains
CV RMSE `0.407`. Random Forest uses RandomizedSearchCV over 540 possible combinations,
sampling 30 combinations with five-fold CV. Its best configuration is 100 trees, maximum
depth 10, minimum split size 10, minimum leaf size 2, and `max_features='log2'`; its CV RMSE
is `0.394`.

## Results
| Model | RMSE (log) | MAE (log) | $R^2$ (log) | RMSE ($) | MAE ($) |
|---|---:|---:|---:|---:|---:|
| Median baseline | 0.575 | 0.432 | -0.015 | 84.06 | 48.51 |
| Tuned Ridge | 0.410 | 0.317 | 0.485 | 59.85 | 36.17 |
| Tuned Random Forest | 0.393 | 0.305 | 0.525 | 58.71 | 35.48 |

The coefficient, impurity-importance, and permutation-importance plots generated by notebook
05 provide the feature-level evidence for Research Question 1. Results should be interpreted
as predictive associations, not causal effects.

## Error Analysis
The Random Forest has the highest mean absolute error for entire-home listings (`$38.58`),
followed by private rooms (`$26.95`) and shared rooms (`$14.14`). The worst 10% of predictions
contains 114 listings and has mean actual price `$274.30`, compared with `$111.73` for the full
test set. The largest observed error is `$445.05`: a private-room listing priced at `$500` was
predicted at approximately `$54.95`.

The error pattern is concentrated in the high-price tail. The supplied predictors describe
room type, size, location coordinates, reviews, satisfaction, and text lengths, but do not
describe premium amenities or host and neighbourhood details. Consequently, listings with
similar observable fields can still have substantially different prices. The full worst-case
table and residual plots are produced by `05_evaluation_and_error_analysis.ipynb`.

## How to Run
1. Install dependencies: `pip install -r requirements.txt`
2. Confirm `data/raw/seattle_01.csv` is present.
3. Run the notebooks **in order**, top to bottom, on a fresh kernel:
   `01_data_audit_and_eda.ipynb` → `02_preprocessing.ipynb` → `03_feature_engineering.ipynb`
   → `04_modeling_and_tuning.ipynb` → `05_evaluation_and_error_analysis.ipynb`
   Each notebook reads the previous notebook's saved output from `data/processed/` or
   `models/`, so they must run in sequence, but each one is independently runnable on a
   fresh kernel as long as the prior notebook's outputs already exist on disk.
4. Outputs are written to `data/processed/`, `models/`, and `figures/`.

## Conclusions
The available listing and review features provide useful predictive signal: the tuned Random
Forest improves substantially over a median baseline and explains about 52.5% of test-set
variation in log price. Accuracy remains imperfect, particularly for expensive entire-home
listings. The strongest limitation is the legacy schema, which excludes several variables
specified in the original research questions. The findings should therefore be understood as
valid for this supplied Seattle export and feature set.
